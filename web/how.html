How this was built

NEMS Open is an open rebuild, in Python, of the model the U.S. government uses for its long-term energy forecast. This page says what was rebuilt, how each piece was checked, and what is still an estimate.

The model it rebuilds

The U.S. Energy Information Administration (EIA) forecasts America's energy to 2050 every year in its Annual Energy Outlook. The forecast comes from the National Energy Modeling System (NEMS): a large Fortran program with a module for each part of the economy. Homes, businesses, factories and vehicles decide how much energy to buy at given prices; power plants, gas, oil and coal markets set prices for that demand. Each year the modules pass numbers back and forth until they agree.

EIA publishes the code. Running it takes paid optimization software and an old Windows build, so almost nobody outside EIA does. NEMS Open makes it something anyone can run, read and change.

Checked against EIA's own code

1. Run EIA's FortranEIA's code is compiled with free tools and run as an "oracle" that records every array at every step.
2. Port one routineEach routine is translated to Python with EIA's quirks kept, even the odd ones.
3. Compare every numberTests compare the Python with the oracle's arrays, usually to within a millionth and a thousandth at worst. A module counts as ported only when they pass.

What is ported today

A green dot means EIA's own code, ported and checked. Amber means our estimate: a curve fitted to EIA's published runs, or our own model of the piece, measured against EIA. Every number on the site takes the grade of the weakest piece behind it.

Where the instant numbers come from

A full run with the ported modules takes about 12 minutes, too long for a slider. So Your 2050 answers from a fitted estimate: a smooth formula fitted to 257 runs of the model's fast loop, shifted so EIA's own settings give EIA's own forecast. On runs left out of the fit it lands within about 1% of a full run. Watch it think replays recorded full runs, pass by pass.

How the Ask box answers

Questions go to Claude, an AI model from Anthropic, which drives the same tools the site uses: it sets levers, runs the estimate and reads results. A program then checks the answer: every number must come from a tool call, and each one gets its source and grade attached. Claude cannot make up a figure, and questions the model cannot answer (a single state, a single plant, a lever that does not exist) are declined.

Who built it

Josh Agarwal, with Claude Code agents working in parallel, one lane per module, each port held to the oracle before it merged. The code is open under the Apache 2.0 license at github.com/joshuaag77-sketch/nems-open.
